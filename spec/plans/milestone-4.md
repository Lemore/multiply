## 1. מה נכנס ומה לא נכנס

**נכנס:**

## 3. Game Logic (`src/game/game.ts`)

הכללים עצמם כבר קיימים. נוסף רק:

```ts
// The home button continues the current game only if one is being played
// in the mode shown in the menu; otherwise it starts a new game.
export function canContinue(state: GameState, selectedMode: PracticeMode): boolean {
  return state.status === 'playing' && state.mode === selectedMode;
}
```

כך הכלל "המשך או התחל" מוגדר במקום אחד, ונבדק ב-Unit Test.

אין שינוי ב-`startGame`: הוא כבר מאפס הכול (תרגיל 1, ניקוד 0, 0 ניסיונות). לכן "שחק שוב" ו"התחל משחק" אחרי `finished` משתמשים באותה פונקציה.

## 4. Unit Tests (`src/game/game.test.ts`)

**ניקוד:**
- משחק שלם (עם `random` קבוע) שבו 7 תרגילים נענים נכון בניסיון הראשון, ו-3 נענים בניסיון השני, השלישי או לא נפתרים בכלל → `firstTryCorrect === 7` ב-`finished`.
- תרגיל שנפתר בניסיון השני → הניקוד לא עולה (קיים, נשאר).
- תרגיל שנפתר בניסיון השלישי → הניקוד לא עולה.
- תרגיל שלא נפתר (חשיפת תשובה) → הניקוד לא עולה.
- משחק שכולו נכון בניסיון הראשון → 10. משחק שכולו שגוי → 0.

**מעברי מצב:**
- `initialGameState` הוא `idle`, ו-`canContinue` מחזיר `false` לכל מצב.
- `idle` → `startGame(7)` → `playing`. `canContinue(state, 7)` = `true`, ו-`canContinue(state, 3)` = `false`.
- `playing` → 10 תרגילים → `finished` (`canContinue` = `false`), והניקוד נשמר.
- `playing` → `startGame` במצב אחר → `playing` חדש: תרגיל 1, ניקוד 0, במצב החדש.
- `finished` → `startGame(state.mode)` → `playing`, תרגיל 1, ניקוד 0, 0 ניסיונות, ובאותו מצב.
- `finished` → `startGame` עם מצב אחר → `playing` במצב החדש.
- ב-`finished`, `submitAnswer` ו-`finishFeedback` לא משנים את המצב.

## 5. App Shell (`src/app/App.tsx`)

**כניסה ל"לימוד" ב-`idle`:** בפונקציה `navigate`, אם `screen === 'learn'` ו-`game.status === 'idle'` → `dispatch({ type: 'startGame', mode: selectedMode })` ואיפוס הטיוטה. ב-`playing` וב-`finished` אין שינוי: המשחק ממשיך, או שמוצג הסיכום (ARCHITECTURE 2.3).

**"שחק שוב":** פונקציה `handlePlayAgain` → `dispatch({ type: 'startGame', mode: game.mode })`, איפוס הטיוטה, ונשארים במסך הלימוד. מועברת ל-`LearnScreen` כ-`onPlayAgain`.

**הלחצן במסך הבית:** `const continueGame = canContinue(game, selectedMode)`. `HomeScreen` מקבל `canContinue={continueGame}`.
- `handleStart`: אם `continueGame` → רק `navigate('learn')`, בלי לשנות את המשחק ובלי לאפס את הטיוטה. אחרת → כמו היום: `startGame(selectedMode)`, איפוס הטיוטה, ומעבר ללימוד.

**השהיה והמשך:** אין שינוי. זה כבר עובד, כי המצב נשמר ב-App Shell. יש רק לכסות בבדיקות.

**אחסון:** אין שימוש ב-`localStorage`, `sessionStorage` או `IndexedDB`. נשאר כך.

## 6. מסך הלימוד – סיכום (`LearnScreen`)

**Prop חדש:** `onPlayAgain: () => void`.

**כשה-`game.status === 'finished'`**, לפי DESIGN.md 1.4 וה-Mockup, מלמעלה למטה:
1. **כותרת "סוף המשחק":** `<h1>` בתוך `SketchFrame variant="dashed"`, באותו מיקום וסגנון של המונה (שימוש חוזר במחלקות `counter` ו-`counterText`).
2. **אזור התוצאה:** ממורכז אנכית בשטח הפנוי (`flex: 1`, `justify-content: center`).
   - התווית **"תשובות נכונות"**: Dust Grey, גופן UI, כ-18px.
   - התוצאה, בשורה אחת: מספר התשובות הנכונות ב-Chalk Amber, המילה "מתוך" ב-Chalk White בגופן UI, והמספר 10 ב-Chalk White. המספרים בגופן Numbers, כ-84px. כיוון RTL רגיל, כך שהשורה נקראת "7 מתוך 10" מימין לשמאל, כמו ב-Mockup.
   - לקורא מסך: התווית והתוצאה נקראות כטקסט רגיל ("תשובות נכונות", "7 מתוך 10").
3. **לחצן "שחק שוב":** `Button variant="secondary"` (קו Chalk Pink), ברוחב מלא, בתחתית אזור התוכן (`margin-block-start: auto`).

**פריסה:** המסך בסיכום מקבל `flex: 1`, כדי שהתוצאה תהיה באמצע הגובה והלחצן בתחתית, מעל הסרגל. ללא גלילה אופקית ב-360–430px.

**אחרי "שחק שוב":** המשחק עובר ל-`playing`, ה-`useEffect` הקיים מחזיר את הפוקוס לתיבת התשובה, והמונה מציג "תרגיל 1 מתוך 10".

**מצב `idle`:** לא אמור להופיע יותר במסך הלימוד, כי הכניסה ל"לימוד" מתחילה משחק. ה-H1 המוסתר "לימוד" נשאר כגיבוי.

## 9. בדיקות ממשק (Vitest + Testing Library)

**`LearnScreen.test.tsx`:**
- ב-`finished` עם ניקוד 7: מוצגים "סוף המשחק" (כותרת), "תשובות נכונות" ו-"7 מתוך 10".
- לחיצה על "שחק שוב" קוראת ל-`onPlayAgain`.
- הבדיקה הזמנית הקיימת של "סוף המשחק" מתעדכנת.

**`HomeScreen.test.tsx`:**
- `canContinue`: הלחצן כתוב "המשך משחק", התפריט פעיל, ולחיצה קוראת ל-`onStart`.
- בלי `canContinue`: הלחצן כתוב "התחל משחק" (קיים).

**`App.test.tsx`** (עם fake timers ו-`Math.random` מדומה):
- משחק שלם שבו 7 תרגילים נענים נכון בניסיון הראשון ו-3 לא → בסיכום "7 מתוך 10".
- תרגיל שנפתר בניסיון השני או השלישי לא נספר.
- "שחק שוב" → "תרגיל 1 מתוך 10", באותו מצב (למשל מצב 7: כל תרגילי המשחק החדש כוללים 7), גם אם בינתיים נבחר מצב אחר בתפריט.
- באמצע משחק: יציאה ל"בית" ול"אודות" וחזרה ל"לימוד" → אותו תרגיל, אותו מספר ניסיונות (למשל: טעות אחת, יציאה, חזרה, ועוד 2 טעויות → חשיפת התשובה), ואותו ניקוד בסיכום.
- באמצע משחק במצב 7, מעבר ל"בית": הלחצן כתוב "המשך משחק", ולחיצה עליו מחזירה לאותו תרגיל, אותם ניסיונות ואותו ניקוד.
- באמצע משחק, בחירת 3 בתפריט: הלחצן משתנה ל"התחל משחק", ולחיצה עליו מתחילה "תרגיל 1 מתוך 10" שבו כל התרגילים כוללים 3. בחירה חזרה ב-7 (לפני הלחיצה) מחזירה את "המשך משחק".
- אחרי הסיכום, הלחצן כתוב "התחל משחק", ולחיצה עליו מתחילה משחק חדש במצב שבתפריט.
- כניסה ל"לימוד" מהסרגל בלי משחק → "תרגיל 1 מתוך 10" במצב שנבחר בבית.
- כניסה ל"לימוד" אחרי סיום המשחק → הסיכום (ולא משחק חדש).
- אחרי משחק שלם, `localStorage` ו-`sessionStorage` ריקים.
- עדכון בדיקת הניווט הקיימת: כניסה ל"לימוד" מתחילה עכשיו משחק.

**בדיקה סטטית:** חיפוש בקוד (`grep`) של `localStorage`, `sessionStorage`, `indexedDB` – אין תוצאות ב-`src/`.
