# MILESTONES – רואים כפול

מסמך זה מחלק את פיתוח האפליקציה לאבני דרך (Milestones). הוא מבוסס על PRD.md, ARCHITECTURE.md ו-DESIGN.md.

**אין Database:** לפי ARCHITECTURE.md, האפליקציה היא Frontend בלבד, ללא Database וללא Backend. לכן אין צורך בסביבות Supabase או ב-Database Migrations.

**פריסה:** כל Push ל-`main` מתפרסם אוטומטית ל-GitHub Pages, בכתובת `https://lemore.github.io/multiply/`, החל מ-Milestone 1. בסוף כל Milestone, הגרסה העדכנית זמינה בכתובת האתר.

---

## Development Execution Rules – כללי ביצוע הפיתוח

> **הנחיה מחייבת ל-AI שמבצע את הפיתוח:**
> 1. יש לפתח את ה-Milestones **לפי הסדר** שמוגדר במסמך זה.
> 2. אחרי השלמת כל Milestone, **יש לעצור** ולהציג למשתמש:
>    - את התוצר שהושלם.
>    - קישור לאתר המפורסם.
>    - את תוצאות הבדיקה מול כל סעיף ב-Definition of Done (עבר / לא עבר).
> 3. **אין להתחיל את ה-Milestone הבא בלי אישור מפורש של המשתמש.**
> 4. אם חסר מידע שנדרש למימוש, כמו נוסח של טקסט, קובץ תמונה או החלטת מוצר, יש לשאול את המשתמש בשפה פשוטה, ולא להמציא.

## Milestone 1 – הקמת הפרויקט ופריסה אוטומטית ✅

**שם ומטרה:** הקמת בסיס טכני עובד ופרוס לאינטרנט, שכל אבני הדרך הבאות יתבססו עליו. זה Milestone טכני, והוא נחוץ כתנאי מקדים לכל השאר.

**מה יש לממש:**
- פרויקט Vite + React + TypeScript, לפי ARCHITECTURE.md.
- `index.html` עם `lang="he"` ו-`dir="rtl"`.
- **Design Tokens גלובליים** לפי DESIGN.md:
  - כל צבעי ה-Color Palette כ-CSS Variables.
  - שלושת הגופנים (Amatic SC, Varela Round, Fredoka), דרך חבילות Fontsource, שמורים מקומית בפרויקט. אין טעינה משרתים חיצוניים.
  - רקע Board Green.
- רכיב `SketchFrame` לקו מתאר "מצויר ביד", שישמש את כל הרכיבים: מסגרות SVG מצוירות מראש, עם עובי קו קבוע וצבע לפי `currentColor` (לפי ARCHITECTURE.md, סעיף 2.3).
- הגדרת Vitest, עם בדיקה בסיסית אחת שעוברת.
- Workflow של GitHub Actions ב-Repository `Lemore/multiply`, שמריץ את הבדיקות, בונה ומפרסם ל-GitHub Pages בכל Push ל-`main`. כולל `base: '/multiply/'`.
- דף זמני שמציג את שם האפליקציה "רואים כפול" בגופן Display.

**תוצר מצופה:** אתר ריק אך מעוצב, עם שם האפליקציה, שזמין בכתובת GitHub Pages ומתעדכן אוטומטית בכל Push.

**Definition of Done:**
- [ ] `npm run dev` מציג מקומית את הדף הזמני בלי שגיאות.
- [ ] `npm run build` ו-`npm test` עוברים בהצלחה.
- [ ] Push ל-`main` מפעיל את ה-Workflow, והוא מסתיים בהצלחה.
- [ ] הדף נגיש בכתובת GitHub Pages, והקבצים נטענים בלי שגיאות 404.
- [ ] הטקסט מוצג בכיוון RTL, בגופן Amatic SC, על רקע `#0C422C`.
- [ ] `SketchFrame` מוצג נכון בכמה גדלים, עם קו בעובי קבוע, ונראה זהה ב-Chrome וב-Safari.
- [ ] בלשונית Network של הדפדפן אין בקשות לשרתים חיצוניים, כמו Google Fonts.

## Milestone 2 – מעטפת האפליקציה, ניווט ומסכי תוכן

**שם ומטרה:** הילד יכול לפתוח את האפליקציה, לעבור בין שלושת המסכים, לראות את מסך הבית ולקרוא את מסך האודות.

**מה יש לממש:**
- **App Shell** שמחזיק את המסך הנוכחי, בלי Router (לפי ARCHITECTURE.md).
- **סרגל ניווט תחתון** עם "בית", "לימוד" ו"אודות", לפי DESIGN.md:
  - אייקונים קוויים.
  - סימון הפריט הפעיל ב-Chalk Amber, עם קו תחתון.
  - הסדר מימין לשמאל.
- **מסך בית** (תצוגה בלבד):
  - שם האפליקציה, עם "כפול" ב-Chalk Amber.
  - תמונה במסגרת Chalk Yellow.
  - התווית "מצב משחק" והתפריט הנפתח, עם "הכול" ו-1 עד 10. התפריט הוא `<select>` רגיל של הדפדפן, שמעוצב במצב סגור. במצב פתוח מוצג הבוחר המובנה של הטלפון.
  - לחצן "התחל משחק".
  - בשלב זה הלחצן רק עובר למסך הלימוד.
- **מסך אודות:**
  - הכותרת "אודות".
  - טבלת לוח הכפל 10×10 כטבלת HTML, עם ערכים שמחושבים בקוד ותאי כותרת (`<th>`), בעיצוב שמוגדר ב-DESIGN.md (LTR, כותרות ב-Amber, אלכסון ב-Yellow).
  - טקסט ההסבר "איך משחקים ב'רואים כפול'?" בנוסח שמופיע ב-DESIGN.md.
  - גלילה כשהתוכן ארוך מהמסך.
- **מסך לימוד:** מסך זמני ריק, שיוחלף ב-Milestone 3.

**תוצר מצופה:** אפליקציה עם שלושה מסכים מעוצבים וניווט עובד ביניהם, פרוסה ב-GitHub Pages.

**Definition of Done:**

- [ ] הסרגל מופיע בכל המסכים, בסדר "בית", "לימוד", "אודות" מימין לשמאל.
- [ ] מסך הבית תואם את ה-Mockups: שם, תמונה, תפריט עם 11 אפשרויות וברירת מחדל "הכול", ולחצן "התחל משחק".
- [ ] טבלת לוח הכפל מציגה ערכים נכונים לכל 100 התאים, בכיוון LTR.
- [ ] טקסט האודות תואם מילה במילה את הנוסח ב-DESIGN.md.

## Milestone 3 – פתרון תרגילים

**שם ומטרה:** הילד בוחר מצב משחק, לוחץ על "התחל משחק" ופותר תרגילים, עם משוב מיידי ועד 3 ניסיונות לכל תרגיל.

**מה יש לממש:**
- **Game Logic** כקוד TypeScript "טהור" (לפי ARCHITECTURE.md):
  - יצירת תרגיל לפי מצב "הכול" או לפי מספר נבחר, בלי חזרה מיידית על אותו תרגיל. פונקציית האקראיות מועברת כפרמטר, כדי שהבדיקות יהיו קבועות.
  - בדיקת תשובה וספירת ניסיונות.
  - חשיפת התשובה הנכונה אחרי 3 ניסיונות שגויים.
- **Unit Tests** לכל הכללים האלה.
- ניהול מצב המשחק ב-`useReducer` ב-App Shell, עם `selectedMode` נפרד למצב שנבחר בתפריט.
- **משוב לשנייה אחת:** כל משוב (הצלחה, כישלון, חשיפת תשובה) מוצג שנייה אחת. אחר כך מוצג התרגיל הבא, או אותו תרגיל לניסיון נוסף אחרי תשובה שגויה. הטיימר נמצא ב-App Shell (לפי ARCHITECTURE.md, סעיף 2.5).
- **חיבור מסך הבית:** "התחל משחק" מתחיל משחק במצב שנבחר בתפריט, ופותח את מסך הלימוד.
- **מסך לימוד**, לפי DESIGN.md:
  - מונה "תרגיל X מתוך 10".
  - התרגיל, בכיוון LTR, עם × ב-Pink.
  - תיבת תשובה: מקלדת מספרית, ספרות בלבד, עד 3 תווים.
  - אזור משוב בגובה קבוע.
  - לחצן "בדיקה".
- **מקלדת בטלפון:** אחרי "בדיקה" הפוקוס חוזר לתיבה, כדי שהמקלדת לא תיסגר. בזמן הצגת משוב התיבה `readOnly`. כשהמקלדת פתוחה, התרגיל, התיבה, אזור המשוב ולחצן "בדיקה" נשארים גלויים.
- **נגישות:** אזור המשוב עם `aria-live="polite"`, ותיבת התשובה עם תווית נגישה שכוללת את התרגיל.
- **מצבי משוב ומצבי תיבת התשובה** (הצלחה, כישלון, חשיפת תשובה; Focus, Correct, Wrong), לפי DESIGN.md.
- **מקרי קצה מה-PRD:**
  - לחיצה על "בדיקה" כשהתיבה ריקה לא נספרת כניסיון, ומוצגת בקשה להקליד תשובה.
  - חסימת לחיצות חוזרות בזמן הצגת משוב.

**תוצר מצופה:** אפשר לבחור מצב, להתחיל ולפתור תרגילים ברצף, עם משוב נכון ומונה שמתקדם.

**Definition of Done:**
- [ ] כל ה-Unit Tests של Game Logic עוברים, כולל:
  - כל תרגיל במצב מספר נבחר כולל את המספר הזה.
  - אין שני תרגילים זהים ברצף.
  - אחרי 3 ניסיונות שגויים, המשחק עובר לתרגיל הבא.
- [ ] בחירת "7" ולחיצה על "התחל משחק" מציגות רק תרגילים שכוללים 7.
- [ ] תשובה נכונה מציגה משוב הצלחה למשך שנייה אחת, ואחריו מוצג התרגיל הבא.
- [ ] תשובה שגויה מציגה משוב כישלון למשך שנייה אחת. אחר כך התיבה ריקה, והתרגיל נשאר.
- [ ] אחרי 3 טעויות מוצגת התשובה הנכונה למשך שנייה אחת, ואחריה מוצג התרגיל הבא.
- [ ] לחיצה על "בדיקה" בזמן הצגת משוב לא נספרת כניסיון.
- [ ] מעבר מסך בזמן הצגת משוב וחזרה ל"לימוד" מציגים את המצב הנכון: התרגיל הבא, או אותו תרגיל לניסיון נוסף.
- [ ] "בדיקה" עם תיבה ריקה לא נספרת כניסיון.
- [ ] אי אפשר להקליד תווים שאינם ספרות, או יותר מ-3 ספרות.
- [ ] במובייל, לחיצה על התיבה פותחת מקלדת מספרית.
- [ ] ב-iPhone וב-Android, כשהמקלדת פתוחה, התרגיל, התיבה, אזור המשוב ולחצן "בדיקה" גלויים, והסרגל התחתון לא מסתיר אותם.
- [ ] המקלדת נשארת פתוחה בין ניסיונות ובין תרגילים.
- [ ] קורא מסך (VoiceOver או TalkBack) מקריא את הודעות המשוב.
- [ ] הגרסה פרוסה ונבדקה בכתובת GitHub Pages.

**מידע נדרש מהמשתמש:** נוסח הודעות ההצלחה, הכישלון וחשיפת התשובה. הנוסח לא מוגדר ב-PRD.

## Milestone 4 – משחק מלא, סיכום והשהיה

**שם ומטרה:** משחק שלם של 10 תרגילים, עם ניקוד, מסך סיכום, "שחק שוב", והשהיה והמשך כשעוברים בין מסכים.

**מה יש לממש:**
- **ניקוד:** תרגיל נספר כנכון רק אם נפתר בניסיון הראשון.
- **מסך לימוד – סיכום** אחרי התרגיל העשירי, לפי DESIGN.md:
  - "סוף המשחק".
  - "תשובות נכונות".
  - "X מתוך 10".
  - לחצן "שחק שוב", שמתחיל משחק חדש באותו מצב.
- **השהיה והמשך:** מעבר למסך אחר משאיר את מצב המשחק בזיכרון. החזרה ל"לימוד" ממשיכה מאותו תרגיל, עם אותו מספר ניסיונות ואותו ניקוד.
- **נעילה בזמן משחק:** בזמן משחק פעיל, התפריט "מצב משחק" והלחצן "התחל משחק" במסך הבית מושבתים, בסגנון Disabled. אחרי סיום המשחק הם חוזרים להיות פעילים.
- **כניסה ל"לימוד" לפני שהתחיל משחק** מתחילה משחק במצב שנבחר במסך הבית.
- **אי-שמירת נתונים:** אין שימוש ב-LocalStorage או באחסון אחר. סגירת האפליקציה מוחקת את המשחק.
- Unit Tests לניקוד ולמעברי המצב (`idle`, `playing`, `finished`).

**תוצר מצופה:** הזרימה המלאה של ה-PRD עובדת מקצה לקצה: בחירת מצב, 10 תרגילים, סיכום ומשחק חוזר.

**Definition of Done:**
- [ ] Unit Tests לניקוד ולמעברי המצב עוברים.
- [ ] משחק שבו 7 תרגילים נפתרו בניסיון הראשון מציג בסיכום "7 מתוך 10".
- [ ] תרגיל שנפתר בניסיון השני או השלישי לא נספר בניקוד.
- [ ] "שחק שוב" מתחיל משחק חדש מתרגיל 1, באותו מצב.
- [ ] יציאה ל"בית" או ל"אודות" באמצע משחק וחזרה ל"לימוד" ממשיכות מאותו תרגיל, ניסיון וניקוד.
- [ ] בזמן משחק פעיל, התפריט והלחצן במסך הבית מושבתים. אחרי הסיכום הם פעילים.
- [ ] כניסה ל"לימוד" בלי משחק פעיל מתחילה משחק במצב שנבחר בבית.
- [ ] רענון או סגירה של האפליקציה מאפסים את המשחק, ואין נתונים שמורים בדפדפן.
- [ ] הגרסה פרוסה ונבדקה בכתובת GitHub Pages.

## Milestone 5 – PWA, עבודה ללא אינטרנט ובדיקה סופית

**שם ומטרה:** אפשר להתקין את האפליקציה על הטלפון, והיא עובדת גם בלי אינטרנט. סיום עם בדיקה כוללת מול ה-PRD.

**מה יש לממש:**
- **vite-plugin-pwa**, לפי ARCHITECTURE.md:
  - Web App Manifest: שם "רואים כפול", `lang: he`, `dir: rtl`, `display: standalone`.
  - `start_url` ו-`scope` לפי ה-Base Path.
- **אייקוני האפליקציה**, כולל Apple Touch Icon.
- **Service Worker** שמבצע Precache לכל קבצי האתר: גופנים, תמונות, JS ו-CSS.
- **אסטרטגיית עדכון:** גרסה חדשה נכנסת לתוקף רק בפתיחה הבאה של האפליקציה, ללא טעינה מחדש אוטומטית באמצע משחק.
- **בדיקה כוללת** של כל הדרישות הפונקציונליות ומקרי הקצה ב-PRD, על Chrome ב-Android ועל Safari ב-iOS.

**תוצר מצופה:** הגרסה הסופית של האפליקציה, ניתנת להתקנה, עובדת ללא אינטרנט, ופרוסה ב-GitHub Pages.

**Definition of Done:**
- [ ] Chrome ב-Android מאפשר להתקין את האפליקציה, והיא נפתחת במצב Standalone עם האייקון והשם "רואים כפול".
- [ ] ב-iOS אפשר להוסיף את האפליקציה למסך הבית דרך Safari, והיא נפתחת עם האייקון.
- [ ] אחרי טעינה ראשונה, האפליקציה נפתחת ופועלת במלואה במצב טיסה, כולל גופנים ותמונות.
- [ ] פרסום גרסה חדשה לא קוטע משחק פעיל, והגרסה החדשה מופיעה בפתיחה הבאה.
- [ ] כל הדרישות ב-PRD, סעיף 4, נבדקו ועברו. רשימת הבדיקה מוצגת למשתמש.
- [ ] הגרסה הסופית פרוסה ונבדקה בכתובת GitHub Pages.

**מידע נדרש מהמשתמש:** תמונת מקור לאייקון האפליקציה. היא לא הוגדרה במסמכי הפרויקט.
